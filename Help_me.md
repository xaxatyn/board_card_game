# Как устроен проект «Подземелье и дураки»

Этот файл — краткий путеводитель по проекту: из каких частей состоит игра,
как они взаимодействуют и как запустить приложение.

## Что это за приложение

Это браузерная многопользовательская карточная игра «Дурак» для 2–6 игроков.
Можно создать комнату, пригласить людей по коду или заполнить места
компьютерными игроками. В игре есть пять ролей с особыми правилами.
Интерфейс доступен на русском и английском языках.

## Используемые технологии

- **Node.js 22.18+ и npm** — среда выполнения и управление пакетами.
- **Next.js 16 (App Router)** — веб-приложение, сборка и серверная часть сайта.
- **React 19 и TypeScript 5** — компоненты интерфейса и статическая проверка типов.
- **boardgame.io 0.50** — игровая модель, лобби, обработка ходов, комнаты,
  синхронизация состояния и подключение по Socket.IO.
- **Tailwind CSS 4** — интеграция CSS; визуальные стили игры находятся
  в `src/app/globals.css`.
- **ESLint 9** — проверка стиля и типичных ошибок JavaScript/TypeScript.
- **Node.js Test Runner** (`node:test`) — модульные тесты правил игры.
- **Render Blueprint** — конфигурация развертывания сайта и игрового сервера,
  описанная в `render.yaml`.

## Как связаны части приложения

1. **Браузер** загружает маршрут `/`, описанный в `src/app/page.tsx`.
   Это клиентский React-компонент: он управляет формами, языком, состоянием
   экранов, локальным сохранением подключения и WebSocket-клиентом.
2. При создании комнаты браузер обращается к **Lobby API boardgame.io**:
   создаёт матч с числом мест и ролями, затем подключает хозяина и выбранных
   ботов. Другой участник входит по коду комнаты.
3. **Игровой сервер** из `src/server.mjs` загружает правила из
   `src/lib/durak.mts` и слушает порт `3101` (или значение `PORT`, заданное
   платформой). Веб-сайт и игровой сервер работают как отдельные процессы.
4. Когда все места заняты, клиенты подключаются к матчу через Socket.IO.
   Сервер проверяет каждый ход и рассылает обновлённое состояние.
5. Сервер хранит полные руки, но `playerView` в `src/lib/durak.mts` отдаёт
   игроку только его собственные карты. Соперникам видны числа карт, а не
   их состав. Клиент не может заменить серверные проверки правил.
6. Если в комнате есть компьютеры, браузер создателя комнаты запускает
   отдельный boardgame.io-клиент для каждого бота. Бот выбирает ход с помощью
   `chooseBotAction`, а сам ход всё равно проверяется сервером.

### Основные файлы

- `src/app/page.tsx` — настройка игроков и ролей, создание/вход в комнату,
  ожидание подключения, игровая доска, история ходов и действия ботов.
- `src/app/layout.tsx` — корневой HTML-макет и метаданные сайта.
- `src/app/globals.css` — оформление экранов, карт, стола и мобильной версии.
- `src/lib/durak.mts` — типы состояния, колода, правила, ходы, приватный
  вид состояния для каждого игрока и стратегия компьютерного игрока.
- `src/lib/translations.ts` — все подписи интерфейса на русском и английском.
- `src/lib/durak.test.mjs` — автоматические тесты ключевых игровых правил.
- `src/server.mjs` — отдельный сервер комнат и игровых подключений.
- `next.config.ts` — разрешение доступа к сайту из локальной сети и настройка
  загрузки CSS в Turbopack.
- `render.yaml` — настройки двух веб-сервисов Render.
- `package.json` — зависимости и команды разработки, тестирования и сборки.

## Правила и роли

- Колода состоит из 52 карт. Обычная роль получает до 6 карт, Варвар —
  до 8. Начинает игрок с самой младшей козырной картой.
- Атаковать можно одной или несколькими картами одного номинала.
  Подкидывать могут два активных места по соседству с защищающимся.
- Защита выбирается для каждой конкретной карты атаки. Обычную карту бьют
  старшей картой той же масти или козырем; козырь бьёт некозырную карту.
- До начала отбивания защищающийся может перевести атаку совпадающей картой.
  Если игрок без карт имеет доступный возврат, перевод может вернуть его
  в игру. Варвара вернуть нельзя; у остальных доступно не более двух возвратов.
- После полного отбивания есть одно дополнительное окно для подкидывания.
  После успешного отбивания атакует бывший защищавшийся; после взятия карт
  атакует следующий активный игрок после него.
- **Паладин** запрещает подкидывание следующему игроку по кругу.
- **Варвар** начинает с 8 карт и не возвращается в игру переводом.
- **Вор** до 3 раз за игру, не чаще раза за раунд, выбирает соперника
  с более чем одной картой и забирает одну из показанных случайных карт.
- **Некромант** до 5 раз за игру, не чаще раза за раунд, возвращает одну
  из шести последних карт отбоя.
- **Реверс** может отбить карту картой меньшего номинала той же масти.
- Игра заканчивается после исчерпания колоды, когда остаётся не более
  одного игрока с картами.

Точные ограничения действий находятся на сервере в `src/lib/durak.mts`;
при изменении правил обновляйте тесты в `src/lib/durak.test.mjs`.

## Запуск на компьютере с Windows

Откройте PowerShell в папке проекта `C:\WEB\DEV\board_card_game`.
Установите зависимости один раз:

```powershell
npm ci
```

Для разработки нужны два открытых окна PowerShell:

1. В первом запустите игровой сервер и оставьте его работать:

   ```powershell
   npm run game-server
   ```

   По умолчанию он будет слушать порт `3101`.
2. Во втором запустите сайт:

   ```powershell
   npm run dev
   ```

3. Откройте адрес Next.js, обычно `http://localhost:3000`. Создайте комнату
   или введите код уже созданной комнаты.

Оба процесса должны работать всё время игры. Для подключения по локальной
сети откройте сайт через IPv4-адрес компьютера, например
`http://192.168.0.107:3000`, и разрешите соединение в частной сети, если
Windows покажет запрос брандмауэра. При перезапуске игрового сервера комнаты
сбрасываются.

## Переменные окружения

- `PORT` — порт игрового сервера; по умолчанию `3101`.
- `CLIENT_ORIGIN` — список разрешённых источников для игрового сервера через
  запятую. Если значение не задано, сервер разрешает `localhost:3000` и
  определённые локальные IPv4-адреса компьютера.
- `NEXT_PUBLIC_GAME_SERVER_URL` — публичный адрес игрового сервера для браузера.
  В режиме разработки по умолчанию используется текущий адрес сайта с портом
  `3101`; в production переменную нужно задать.

Не добавляйте секреты в переменные с префиксом `NEXT_PUBLIC_`: они доступны
в клиентском JavaScript. Настройки Render в `render.yaml` задают адрес сайта
для сервера и адрес сервера для сайта.

## Публикация в интернете и подключение домена

### Что понадобится

- Аккаунт у хостинг-провайдера, который поддерживает Node.js 22.18 или новее.
- Два работающих веб-сервиса: один для Next.js-сайта, второй для игрового
  сервера boardgame.io. В текущем проекте их настройки для Render уже есть
  в `render.yaml`.
- Возможность принимать WebSocket-подключения к игровому серверу. Одного
  статического хостинга для сайта недостаточно: на нём нельзя запустить
  сервер комнат.
- Доступ к DNS-настройкам домена. Удобнее выделить два поддомена, например
  `play.example.com` для сайта и `game.example.com` для игрового сервера.
- Для непрерывной работы — тариф без автоматического выключения. Постоянная
  база данных нужна, если комнаты должны переживать перезапуск сервера.

Фиксированного требования к объёму памяти или числу ядер в проекте нет:
нагрузка зависит от количества одновременных комнат, а доступные ресурсы
задаются тарифом хостинга. Для начала используйте самый маленький тариф,
на котором поставщик поддерживает указанную версию Node.js, сборку Next.js
и постоянно работающие WebSocket-соединения. Если при сборке или игре
сервису не хватает ресурсов, увеличьте тариф по показателям хостинга.

### Развёртывание на Render

1. Отправьте актуальный код в GitHub и убедитесь, что в корне репозитория
   доступны `render.yaml`, `package.json` и `package-lock.json`.
2. В Render выберите создание Blueprint из GitHub-репозитория и подтвердите
   создание обоих сервисов из `render.yaml`:
   - `durak-app` — сайт: `npm ci && npm run build`, запуск `npm start`;
   - `durak-game-server` — комнаты и игра: `npm ci`, запуск
     `npm run game-server`.
3. Дождитесь успешного развёртывания. Render выдаст каждому сервису свой
   адрес `onrender.com`. Откройте настройки окружения обоих сервисов и
   установите реальные адреса, выданные Render:
   - для `durak-app`: `NEXT_PUBLIC_GAME_SERVER_URL` — HTTPS-адрес игрового
     сервиса, например `https://durak-game-server.onrender.com`;
   - для `durak-game-server`: `CLIENT_ORIGIN` — HTTPS-origin сайта,
     например `https://durak-app.onrender.com`, без пути и без завершающего
     `/`. Если значение содержит несколько сайтов, перечислите их через
     запятую.
4. Если Blueprint после синхронизации восстанавливает прежние значения,
   измените URL также в `render.yaml` и повторно синхронизируйте Blueprint.
   Затем выполните повторное развёртывание обоих сервисов.
5. Проверьте сайт, создание и вход в комнату из двух браузеров, обновление
   состояния игры и соединение игроков. Игровой сервер должен оставаться
   доступен отдельно от сайта.

Пользовательская переменная `PORT` для Render не нужна: игровой сервер
читает её автоматически. Бесплатный тариф Render может усыплять сервисы,
а сервер использует память процесса для комнат. Поэтому после простоя
подключение может запускаться с задержкой, а перезапуск или остановка сервиса
удаляет действующие комнаты.

### Подключение своего домена

1. Купите домен или используйте уже имеющийся. Сначала разверните оба сервиса
   и добавьте собственные домены в настройках соответствующих веб-сервисов
   Render: `play.example.com` — для `durak-app`, `game.example.com` — для
   `durak-game-server`.
2. Render покажет инструкции для DNS. У регистратора домена создайте записи,
   указанные именно для каждого сервиса. Обычно для поддомена это CNAME;
   адрес назначения копируйте из панели Render, а не угадывайте.
   Для корневого домена (`example.com`) используйте поддерживаемый вашим
   DNS-провайдером способ, который предлагает Render (например, ALIAS/ANAME
   или A-запись).
3. Дождитесь проверки DNS и выпуска HTTPS-сертификатов в Render. Пока
   домен не подтверждён и HTTPS не активен, не переключайте на него
   публичный адрес игрового сервера.
4. Обновите переменные окружения обоих сервисов:

   ```text
   NEXT_PUBLIC_GAME_SERVER_URL=https://game.example.com
   CLIENT_ORIGIN=https://play.example.com
   ```

   Если нужно оставить доступ по адресу Render, добавьте его к
   `CLIENT_ORIGIN` через запятую, например
   `https://play.example.com,https://durak-app.onrender.com`.
5. Если значения заданы Blueprint-файлом, обновите соответствующие
   URL в `render.yaml`, чтобы следующее применение конфигурации не вернуло
   старые домены. После этого повторно разверните оба сервиса и проверьте
   создание комнаты и подключение по новому домену.

Подойдёт и другой хостинг, но он должен обеспечивать те же условия:
развёртывание двух Node.js-процессов, передачу платформенного `PORT`,
HTTPS для сайта, WebSocket/secure WebSocket для игрового сервера и настройку
допустимого origin сайта на игровом сервере. На хостинге с собственным
доменным маршрутизатором назначьте разные поддомены двум сервисам либо
настройте проксирование WebSocket. Один поддомен для обоих сервисов
потребует отдельной настройки маршрутов и не является текущей конфигурацией.

Перед передачей публичной ссылки проверьте, что оба сервиса доступны через
HTTPS и игроки могут создать комнату, присоединиться и выполнить несколько
ходов. Не публикуйте секретные ключи и пароли в репозитории или в
`NEXT_PUBLIC_` переменных.

## Данные и ограничения

В текущей конфигурации boardgame.io использует хранилище в памяти процесса.
Комнаты не сохраняются после перезапуска игрового сервера; постоянная база
данных пока не настроена. На бесплатном Render сервис может временно
останавливаться. Для работы компьютерных игроков браузер хозяина комнаты
должен оставаться подключённым.

Сведения о последней комнате и credentials подключения браузер сохраняет
в `localStorage`, чтобы восстановить соединение после обновления страницы.
Это не означает, что сама партия записана на диск сервера.

## Полезные команды

```powershell
npm run test:game  # Проверить правила игры
npm run lint       # Проверить код ESLint
npx tsc --noEmit   # Проверить типы TypeScript
npm run build      # Собрать production-версию сайта
npm start          # Запустить production-сайт после сборки
```

Тесты проверяют раздачу, атаку, защиту, переводы, возвраты, способности ролей
и приватность игровых карт. Сервер комнат для запуска тестов не требуется.
